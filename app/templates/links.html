Every pair, compared in groups shows the model a set of items at a time and asks which of them connect. It still covers every pair — the sets are tiled so each pair falls in exactly one of them — but a set of 50 items covers 625 pairs for the same prompt that one-at-a-time spends on 25, because an item is written out once instead of once per pair. That is where the saving comes from, and it is why this is the sensible default.
Only pairs with something in common compares two items when they share a page, a document or a date, or when their wording is close. The quickest, and the only one that can miss a pair outright.
Every pair, one at a time is the same coverage as the first, asked one pair per question so the model has nothing else in front of it. Slowest by a wide margin; worth it only where a missed connection matters more than a day of machine time.
Whichever you pick, a pair is judged once and the answer is kept, so a stopped run resumes rather than starting again and you can do this in stages.
