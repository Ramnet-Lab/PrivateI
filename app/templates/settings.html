Destroy case data

This cannot be undone. There is no archive, no undo and no recycle bin: what this destroys is gone from this machine. The original uploaded files are deleted too — this is not a "clear the database and re-ingest" button. If the only copy of a document is the one uploaded here, that copy is destroyed with it. Download anything that has to survive the case — the transcripts link above, and each report from the report page — before you run this.

A document being processed right now is stopped rather than left running, so nothing it was part-way through writing comes back after the purge. Nothing here touches the model endpoint, the API key or the investigation objective: those are configuration, not case material, and they survive every scope below.

What to destroy

Destroys every uploaded document: the original files, the rendered page images, the read text, the facts extracted from them, the entities derived from those facts, the passages the chat page searches, and everything about them in the graph. Leaves the saved reports, the objective and the model settings. Reports already written stay readable, but the documents they cite are gone, so nothing in them can be checked against the record again.

Destroys every saved report. Leaves every document, its text, its facts, the graph, the objective and the model settings, so a report can be written again from the same corpus — though not identically, because each run samples with its own seed.

Both of the above in one action: no documents, no originals, no pages, no text, no facts, no entities, no graph, no reports. Leaves only the objective and the model settings, so the application is ready for the next case rather than needing to be set up again.
